# NextTech AI Support Bot v6.3.0

v6.3.0 consolidates the reliability, retrieval, security, and distributed-runtime work added after the original v6 release into one documented application release.

## Highlights

- Hybrid RAG using BM25 plus semantic embeddings.
- Managed knowledge documents/chunks with reindexing.
- Gemini/provider abstractions and provider-reported token metrics.
- Signed browser sessions with secure cookie transport.
- Persistent webhook idempotency and crash-recovery leases.
- Durable transactional delivery outbox with retries and dead-letter state.
- Redis-backed distributed rate limiting.
- Redis pub/sub realtime SSE with database reconciliation and local fallback.
- Transaction-safe realtime publication: messages are emitted only after commit.
- One canonical browser SSE route; the legacy duplicate polling route was removed.
- Production Docker, migration, lint, security, test/coverage, and image-build CI gates.

## Deployment notes

Before deployment:

1. Back up PostgreSQL and run `alembic upgrade head`.
2. Set `ENVIRONMENT=production`.
3. Configure long independent `JWT_SECRET_KEY` and `WEB_SESSION_SECRET` values.
4. Configure `REDIS_URL` and `REDIS_REQUIRED=true` for multi-replica production.
5. Run the outbox worker alongside the API.
6. Keep `WEB_SESSION_COOKIE_SECURE=true` behind HTTPS.
7. Configure `TRUST_PROXY_HEADERS=true` only behind a proxy/load balancer that sanitizes forwarding headers.
8. Configure WhatsApp and other integration credentials only in the deployment secret store.

After deployment verify `/health`, `/ready`, login, web chat, SSE agent replies, human handoff, knowledge retrieval, feedback, the outbox worker, and configured external channels.

## Compatibility

The public browser chat, agent dashboard, WhatsApp webhook, agent/admin API surface, and database-backed conversation flow remain compatible with the v6 line. The browser event path remains `/web/conversations/{conversation_id}/events`; only the duplicate legacy implementation was removed.

## Known environment responsibilities

Hosting, managed PostgreSQL/Redis, TLS/domain configuration, secret management, backups, monitoring/alerts, and real third-party credentials remain deployment-specific responsibilities and are intentionally not embedded in the repository.
